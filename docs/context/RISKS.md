# RISKS: 风险清单与高危操作红线

本文档记录本项目已确认的技术风险、生产运维红线、验证缺口及保护措施。涉及相关风险区域时必须先行查阅。

---

## 1. 生产运维与目录踩坑风险 (极高危 🔴)

### 风险描述: AstrBot 插件反射扫描机制引发的崩溃死锁
- **触发场景**: 在 VPS 远程排查或更新插件时，习惯性在当前目录执行 `cp -r cs2_results cs2_results.bak` 或建立临时测试文件夹。
- **灾难后果**: AstrBot 启动时会反射扫描 `/opt/astrbot/data/plugins/` 目录下的**所有子文件夹**并尝试装载为独立插件。当扫描到非标准结构（或代码完全相同的副本）时，会抛出类重名冲突、事件处理器绑定重复，甚至导致主进程启动异常卡死。
- **铁律预防措施**:
  - 严禁在 `/opt/astrbot/data/plugins/` 及其任何子路径下放置任何备份、临时文件或压缩包。
  - **唯一指定备份路径**: 宿主机 `/root/backup_plugins/`。

---

## 2. 反爬与 IP 信誉恶化风险 (高危 🟠)

### 风险描述: 遭遇 Cloudflare 403 连锁反应导致全局服务冻结
- **触发场景**:
  1. 并发抓取 HLTV 防爬严格的动态接口（典型如 `/stats/players/individual/...`）。
  2. 在短时间内发起高频重试，导致 Cloudflare 将机房 IP 标记为恶意爬虫。
- **连锁后果**:
  - `_record_challenge()` 记录连续失败，触发指数退避机制（从 5 分钟递增至 60 分钟）。
  - 在退避期间，所有非关键抓取全部被抑制（`suppressed`），赛程更新停滞、赛果推送延迟。
- **防御与缓解措施**:
  - 核心查询逻辑坚决贯彻“本地缓存优先”，严禁每个用户命令都直击网络。
  - 对于易吃盾的冷门页面（如选手近 90 天 stats），设计短超时熔断机制，超时立即返回基础资料卡，绝不反复 reload 死等。
- **证据记录**: 参见历史现场排查 [2026-10-cf-performance-audit.md](history/2026-10-cf-performance-audit.md)。

## 3. 并发死锁与浏览器单锁饥饿风险 (高危 🟠)

### 风险描述: `_browser_operation_lock` 全局单锁排队积压
- **触发场景**:
  - 某个抓取操作（如 `fetch_search` 或详情页打开）在 `_browser_operation_lock` 内部遇到了页面网络卡顿、CF 盾等待或 `min_gap: 90s` 强冷却。
- **后果**:
  - 全局只有一个浏览器操作锁，后续所有需要浏览器的指令（包含群成员发送的战队/选手查询、后台赛事追踪）全部卡在锁外排队。
  - 排队队列无上限积压，用户在群聊发出的指令延迟可能从几秒飙升至十几分钟。
- **防御与缓解措施**:
  - 缩短单个页面在持锁状态下的总等待预算（`cs2_fetch_budget_seconds`）。
  - 在进入持锁浏览器操作前，通过本地名录预过滤 95% 以上的解析请求。

## 4. 交付合规与发布规范风险 (中危 🟡)

### 风险描述: GitHub Release 附带内部测试流水账破坏用户体验
- **触发场景**: 开发者将本地命令行的 `pytest` 结果、VPS 实机环境检测日志等调试信息机械复制到公开 Release Notes 中。
- **后果**: 破坏面向玩家群体的清晰度，造成不专业的展示效果。
- **铁律预防措施**:
  - Release 说明必须严格按照用户交付格式书写，仅呈现业务功能特性、体验优化与 Bug 修复列表。

---

## 5. 代理执行环境与长命令超时失步风险 (中危 🟡)

### 风险描述: 前台耗时命令突破反重力 10 秒等待阈值转异步
- **触发场景**:
  - AI Agent 在验证修改时，直接在前台执行耗时过长的命令（如无针对性地全量运行 117+ 个单测用例）。
- **后果**:
  - 反重力任务调度系统内置了 10 秒等待上限（`WaitMsBeforeAsync: 10000`）。一旦超过 10 秒未跑完，调度器会强行将该命令转为异步后台任务并派生子任务（如 `task-xx`）进行监控。
  - 这容易造成控制台输出信号断裂、上下文状态丢失，甚至导致 Agent 陷入对后台任务的盲目轮询，严重影响任务流的连续性与可靠性。
- **防御与缓解措施**:
  - 日常代码修改严格遵循**定向模块验证原则**（如优先执行 `pytest tests/test_names.py`，耗时仅百毫秒级）。
  - 若确需执行全量回归或构建打包等不可避免的长任务，必须合理预先配置超时预期，利用系统被动事件通知机制唤醒，严禁死循环轮询任务状态。
