本文档记录本项目已确认的技术决策、选型理由、作用范围与背景来源。

## ADR-01: 排行榜卡片采用纯本地 SQLite 查询，零网络请求

- **状态**: 已确认并在生产运行
- **生效范围**: `render.py` (`render_vrs_ranking_card`, `render_hltv_ranking_card`), `main.py`
- **背景与冲突**: 新增 `/cs2 排名 [vrs|hltv]` 时，若每次用户触发都实时打 HLTV 榜单页，会导致高频触发 Cloudflare 5 秒盾挑战，且单次出图耗时将飙升至 5~15 秒以上。
- **裁决方案**: 充分复用插件已有定时名录任务同步入库的 `team_index` (HLTV 榜 ~263 队) 与 `vrs_ranking` (Valve 榜 ~350 队) 数据。
- **影响与收益**: 渲染榜单卡片全量数据直接读 SQLite，零网络请求，出图时间稳定在 **1~3 秒以内**，彻底阻断在线网络风控。
- **来源与记录**: 参见历史归档 [2026-10-ranking-and-alias-evolution.md](history/2026-10-ranking-and-alias-evolution.md)。

## ADR-02: 抓取底座以 Playwright 有头/屏幕外为基石，保留 curl_cffi 旁路

- **状态**: 已确认并在生产运行
- **生效范围**: `fetcher.py`, `hltv.py`
- **背景与冲突**: HLTV 在非家用 IP（尤其是机房 IP 如香港 VPS）全面部署了 Cloudflare 动态挑战。单纯依赖 TLS 指纹模拟（如 curl_cffi）无法直接通过 5 秒盾和 Turnstile 验证码。
- **裁决方案**:
  1. 主通道采用 Playwright 无头/屏幕外浏览器结合虚拟显示服务 (Xvfb) 启动真实 Chromium 渲染环境，具备自动过盾能力与 VNC 人工验证支持。
  2. 设计 `curl_cffi` 高速旁路，在有效 Cookie/凭证存在时加速静态资源及接口读取。
- **影响与收益**: 虽浏览器开销较高，但保证了数据采集的最终可用性与稳定性；当凭证失效时平滑降级。

## ADR-03: 反爬调度引入公平优先级单属主节流门 (_FairPriorityGate)

- **状态**: 已确认并在生产运行
- **生效范围**: `fetcher.py`
- **背景与冲突**: 后台自动化轮询（直播赛况、Matches 列表扫描、资讯检查）与用户前台交互指令（查排名、查战队、添加订阅）共享同一个抓取会话。若无调度器，用户指令会被阻塞在后台队列末尾。
- **裁决方案**: 实现单属主优先级门禁。定义 `PRIORITY_USER` (用户前台) 具有最高插队权；后台任务每等待 4 次授权自动提升有效等级防饥饿，并在授权之间硬性锁定 `min_gap` 冷却期。
- **影响与收益**: 保护 IP 免遭封禁的同时，极大限度保证用户交互指令的实时性。

## ADR-04: 中文俗称与外号映射词典 (names.py) 算法设计

- **状态**: 已确认并在生产运行
- **生效范围**: `names.py`
- **背景与冲突**: 玩家输入习惯极为复杂，涉及缩写、谐音、错别字及黑称（如 `小科维奇`、`孩贼王`、`大表哥`、`银河战舰`），直接字符串匹配极易漏判。
- **裁决方案**:
  1. 维护硬编码但持续演进的字典映射：`_TEAM_ALIASES` 与 `_PLAYER_ALIASES`。
  2. 采用大小写折叠 (`casefold`) 与无空格/标点归一化算法（`cf()`）统一索引。
  3. 引入世界排名权重裁决：当一个俗称对应多个候选对象时，依据权威榜单排名最高的活跃选手进行智能仲裁（`_choose_by_rank`）。
- **影响与收益**: 极佳的用户体验，同时支持中文拼音/汉字输入直达 HLTV 英文官方索引。
